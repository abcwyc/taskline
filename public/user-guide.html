01开始使用

登录：访问你的 Taskline 地址（自托管时通常是 http://你的服务器:3000），输入邮箱和密码。如果管理员为你开启了双重验证，还需要输入验证器 App 上的 6 位动态码；绑定过 Passkey 的用户也可以直接点「Sign in with a passkey」用指纹 / 人脸登录。

获取账号：Taskline 默认是邀请制。联系工作区管理员在「成员」页生成邀请链接，打开链接即可设置密码加入。第一位管理员由部署者在初始化时创建。

界面速览

  • 左侧边栏：收件箱、我的问题、以及工作区（计划 / 项目 / 视图 / AI 助手 / Reviews / 团队 / 成员）和你的团队列表。界面语言跟随浏览器，支持中英文。
  • 顶部命令面板：按 ⌘+K（Windows 为 Ctrl+K）随时呼出——搜索 Issue / 项目 / 计划 / 文档，或直接执行动作（如 Create new issue）。
  • 团队子页：每个团队下有 首页、问题（全部 / 活跃 / Backlog）、周期、计划、项目、视图 等标签页。
新创建的 Issue 默认不指派、归属团队由系统按「项目 → 周期 → 第一个团队」决定。创建成功后通知条会显示编号（如 LNUI-1004 created），点 View 直接跳到该 Issue。

02核心概念：Issue

Issue 是一切工作的最小单元，编号形如 LNUI-703。

✍️

创建

侧边栏编辑按钮或命令面板 → Create new issue；支持从模板预填标题与描述，可勾选「创建多个」连续录入。

🚦

状态流转

Todo → In Progress → Done… 状态可由管理员自定义（见设置），拖动或点击状态图标即可流转。

💬

评论与协作

支持富文本评论（代码块 / 清单 / 引用）、@邮箱提及、表情回应；自己的评论可编辑或删除。

🔗

关系与子任务

建立 Blocked by / Blocks / Related / Duplicate 关系；添加子 Issue 拆解工作； 附件直接拖入。

Issue 详情页右侧面板

  • Properties：状态、优先级（Urgent→No priority 五档）、负责人、所属周期；
  • Labels：点标签旁的 + 打开选择器，多人协作时用颜色标签分类；
  • Project / Milestone：归入项目与里程碑；
  • Relations / Diffs：阻塞关系与关联的 Pull Request（可手动添加标题 + 链接）。

视图与筛选

列表支持按状态分组、按优先级排序；顶部「Filter」用 ⌘F 风格的筛选条组合条件（状态 / 优先级 / 负责人 / 标签）。「我的问题」页按 Assigned / Created / Subscribed / Activity 四个标签组织与你相关的工作。

03团队与周期（Cycles）

团队是 Issue 的组织单位；周期是团队的两周（可自定义）冲刺节奏。

  • 当前周期：燃尽图实时展示 Scope（总量）、Started（已开始）、Completed（已完成）与理想完成线，容量占用一目了然。
  • 规划：把 Issue 拖入 / 移出周期；周期结束后查看成功率（完成 / 总量）。
  • Triage：每个团队有收件队列（外部请求、客户反馈先进 Triage），在「Accept → 变成正式 Issue」或「Decline / Snooze」之间处理。

04项目（Projects）与里程碑

项目是跨周期的更大交付单元，归属某个团队、可挂到公司级「计划」（Initiative）下面。

  • 概览页：富文本描述、资源链接、成员、健康度（进展顺利 / 存在风险 / 偏离计划）。
  • 里程碑：勾选完成、重命名、调整目标日期、删除——全部即时保存。
  • 进展更新：在「活动」标签页发布带健康度的更新（如「进展顺利：核心链路已合并」），所有更新按月归档，管理员或作者可删除。
  • 进度：项目完成度 = 已完成 Issue / 总 Issue，自动计算，无需手工维护。
计划（Initiatives）目前提供列表与项目关联；「写计划更新」等入口为占位提示，属于后续版本能力。

05收件箱与通知

收件箱聚合所有与你相关的事件：被评论、被 @、被指派、状态变更、问题被阻塞等。

  • 预览面板：点击任意通知，右侧直接展示对应 Issue 的完整详情，可就地评论（⌘↵ 发送）或附加文件，无需跳转。
  • 整理：单条通知可 已读 / 未读 / 小睡（1 小时 / 3 小时 / 明天）/ 删除；顶部可「全部已读」与「清空」。
  • 偏好：在 设置 → Notifications 选择接收哪些类型（评论 / 提及 / 指派 / 状态），可选开启邮件通知（需管理员配置 SMTP）。

06代码评审（Reviews）

Taskline 内置轻量评审流，不依赖 GitHub 等外部仓库——适合私有代码或非代码变更（设计方案、SQL 脚本）的评审。

  1. 创建：Reviews 页 → New review，粘贴 git diff main...你的分支 的输出。系统自动解析出文件清单、增删行数，并区分实现 / 测试文件。
  2. 评审：Diff 标签页查看着色差异，可对整个评审或某个文件发表评论；Guide 页阅读作者的 Summary 与测试计划。
  3. 裁决：Approve（批准）或 Request changes（要求修改）；完成后可标记 Merged / Closed。作者会收到站内（及可选邮件）通知。
评审内容保存在 Taskline 数据库中，不会回写到任何 Git 服务器；它不替代 GitHub/GitLab 的代码托管与合并。

07AI 助手（Agent）

工作区内置 AI 对话助手，理解你的项目上下文（团队、项目、当前未完成的 Issue）。

  • 入口：侧边栏「AI 助手」；对话历史保存在服务器，可随时回看。
  • 能问什么：「什么在阻塞团队？」「按优先级总结未完成的工作」「帮我规划本周」等。回答基于真实的 Issue 数据，不会编造编号。
  • 个性化：设置 → Agent personalization 写下你的偏好（如「回答用中文、优先关注我负责的 Issue」）；管理员可在 设置 → AI & Agents 配置工作区级提示词与模型。
AI 需要管理员配置 OpenAI 兼容端点（AGENT_LLM_* 环境变量）并在设置中启用。未配置时助手会明确提示不可用，不会假装回答。

08文档、Triage 与其他功能

📄

团队文档

每个团队有文档区：新建文件夹（支持 emoji 图标）、创建 / 重命名 / 置顶 / 删除文档，固定常用文档到团队首页。

📥

Asks / 客户请求

设置 → Asks 提交请求（选团队、写描述），系统分配 REQ-n 编号并进入该团队 Triage 队列；Customer requests 页集中查看所有待处理请求。

📊

Pulse 分析

设置 → Pulse：每周创建趋势、状态分布、成员负载、优先级占比四张图，全部基于工作区真实数据。

🏷️

标签与状态定制

管理员可在设置中维护 Issue 标签（含描述）、项目标签，以及自定义工作流状态（名称 / 颜色 / 分类 / 图标），新建状态立即出现在所有选择器中。

⏱️

SLA

按优先级配置响应 / 解决时限，页面实时监控超时的未完成 Issue。

🚀

Releases

跨项目聚合所有里程碑为一条发布时间线，直接勾选「已发布」。

10安全：MFA / Passkey / API Key

全部在 设置 → Security & access：

  • 两步验证（TOTP）：Enable two-factor → 用验证器扫码 → 输入 6 位码确认。之后每次登录需输入动态码；关闭需验证账户密码。
  • Passkey：为设备注册指纹 / 人脸 / 硬件密钥，登录页一键免密登录。支持多设备多把钥匙，可随时删除。
  • API Key：为脚本 / CI 生成 circle_… 密钥（仅创建时展示一次），以 Authorization: Bearer <key> 调用全部 REST API，权限等同你本人。可随时吊销。
  • 会话管理：「Sign out all sessions」一键注销所有已登录设备（改密码同样会全端下线）。
忘记密码联系管理员：管理员可在成员列表为你生成一次性重置链接（30 分钟有效），无需邮件服务。

11管理员指南：部署与运维

Docker Compose 部署（推荐）

# 1. 准备环境变量
cp .env.example .env
#    必填：POSTGRES_PASSWORD、AUTH_SECRET（npx auth secret 生成）、AUTH_URL
#    可选：SIGNUP_MODE=invite（默认）、BOOTSTRAP_SECRET、CRON_SECRET

# 2. 启动
docker compose up -d --build

# 3. 创建第一位管理员
#    设置 BOOTSTRAP_SECRET 后访问 /sign-up，或：
curl -X POST http://localhost:3000/api/bootstrap \
  -H "Authorization: Bearer $BOOTSTRAP_SECRET" \
  -H "content-type: application/json" \
  -d '{"email":"admin@example.com","password":"a-strong-password","name":"Admin"}'

可选能力开关

能力环境变量未配置时
AI 助手AGENT_LLM_BASE_URL / _API_KEY / _MODEL（任意 OpenAI 兼容网关）助手页明确提示未启用，其余功能不受影响
邮件通知SMTP_URL 或 SMTP_HOST/PORT/USER/PASS + MAIL_FROM仅站内通知，邮件静默跳过
周期快照CRON_SECRET + 每日定时调用 POST /api/jobs/cycle-burnup燃尽图使用种子 / 手动数据

日常运维

  • 备份：pnpm backup 导出数据库快照 + 附件包（含校验和）；恢复用 scripts/restore.sh。请把备份拷贝到主机之外。
  • 健康检查：GET /api/health 返回进程与数据库状态，可接入监控。
  • 安全基线：TLS 在反向代理终止（deploy/nginx.conf.example 提供参考配置）；保持邀请制注册；生产环境绝不执行 db:seed（会创建演示账号）。
  • 角色：Admin 管理成员 / 团队 / 工作流状态 / 工作区设置；Member 正常读写；Guest 只读 + 可评论 / 提请求。

12能力边界与常见问题

当前版本不包含（诚实边界）

  • 无 VCS 集成：评审通过粘贴 diff 创建，不会自动同步 GitHub/GitLab 的 PR；
  • 无第三方集成：Integrations / Connected accounts 页面为参考目录，暂无可连接的 SaaS；
  • 通知无推送：站内 + 可选邮件，没有浏览器 / 手机推送；
  • 计划（Initiative）更新：暂不支持发布计划级进展更新。

常见问题

Q：创建的 Issue 在「我的问题」里看不到？
新 Issue 默认未指派，「我的问题」默认显示 Assigned 标签。切到 Created 标签即可看到，或点击创建成功通知上的 View 直接打开。

Q：改了工作流状态，旧 Issue 会受影响吗？
使用中的状态不可删除（按钮会禁用并提示），避免历史 Issue 失去状态。

Q：API 返回 401？
检查密钥是否以 Bearer circle_… 形式携带、是否已被吊销；密钥只在创建时展示一次，丢失请重新生成。
